# 护卫队训练签到小程序

基于用户上传的 guard-checkin.zip 整理。主要流程：微信登录 → 绑定名单账号 → 管理员选择校区、导入名单 → 发起签到 → 队员扫码、现场拍照并提交 → 管理员核对、补签或请假 → 月度统计和 CSV 导出。

## 开发与验证

使用 Node.js 18 或更新版本。云环境已验证 Node.js 24。

```sh
cd /workspace/weixin
npm ci --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org --replace-registry-host=always
npm test
```

安装命令使用 npm 官方源，保留锁文件中的版本与完整性校验。上传的锁文件指向 npmmirror，该域名在当前云环境返回 403；通过 npm 支持的 registry 覆盖安装，无需修改锁文件。现有测试覆盖时间与导出逻辑、项目结构，以及模拟微信/云接口下的登录回跳、二维码校验、提交重试、状态恢复和跨校区统计。

在微信开发者工具中导入本目录。`project.config.json` 中目前是 `touristappid`，真实微信登录和真机调试需要在工具中配置自己的 AppID，并确认其已在现有 WorkBuddy Cloud 项目中绑定。前端使用 `utils/cloud.js` 的公开配置，不能在这里填写服务端密钥。上传文件已包含 SDK 的小程序产物 `miniprogram_npm`；更新依赖时使用开发者工具的“构建 npm”。

本项目没有普通浏览器页面或 Node HTTP 服务；`npm test` 是云环境的验证入口，完整运行依赖微信客户端。

## 本次修复

- 登录/账号绑定完成后回到原扫码页，限制可回跳的页面和参数。
- 拒绝缺少令牌、非法场次编号、未来时间或过期二维码；提交前和照片上传后重新校验场次，已有记录不重复提交。
- 提交失败可重试并复用上传结果，拍新照片时清除旧结果；提交期间禁止换照片。
- 会话恢复异常清除旧身份权限；退出接口失败时保留当前状态并显示失败。
- 修复超管“全部校区”的选择恢复；发起签到必须选择具体校区，校验迟到分钟数。
- 签到名单使用场次所属校区；未绑定微信的队员补签显示明确原因。
- 月报页面、汇总 CSV、剪贴板仅将所属校区场次计入应到；其他校区显示“—”。历史场次列表按场次校区计算人数。
- 结束场次后停止刷新并跳转名单；管理页补充身份恢复和入口检查。

## 真机验收与后端前提

压缩包没有后端建表、RPC 或权限策略的源码，因此本次没有部署或验证这些服务。前端已有 members、admins、campuses、sessions、records、app_settings 表及 my_profile、bind_identity、import_members 等 RPC 依赖；需使用原有 WorkBuddy Cloud 服务。

请在微信开发者工具/真机执行：管理员登录并导入一份名单，队员绑定后扫描管理员的二维码、拍照提交，确认重复扫码显示已有记录；结束场次后不可再签到；补签、请假、撤销后核对月报和导出内容。另测登录中断后回跳、相机拒绝授权、上传断网重试、切换校区和跨月统计。

服务端必须独立验证身份、校区、角色、场次开放状态和令牌时效，并对同一场次/队员建立唯一约束。当前 records 写入接口未传递二维码令牌；客户端复查不能代替服务端原子校验，也不能彻底消除上传完成与写入之间的竞态。若要实现可靠的防代签/防篡改，需要配套后端 RPC 接受令牌、校验照片和状态，并由服务端计算迟到。该接口未随附件提供，不能宣称已经完成线上安全验证。
